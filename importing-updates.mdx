The W-G-O NetNavi app gives you four ways to bring in new content: a full `.wgo` package import, a lightweight JSON-only data import, and separate GLB imports for each character's 3D avatar. All four methods live in the **AI Updates** tab, and every import — regardless of method — triggers a diff preview so you can verify the changes before they are applied.

## Import .wgo Package

Use this method for comprehensive daily updates that bundle data, optional avatars, and optional mission images into one file. This is the recommended path when working with packages generated by an AI assistant.

<Note>
  The diff preview shows you a side-by-side summary of what will change: each character's XP before and after the import, the number of new history entries being added, any mission status changes, and whether any XP rules or settings will be updated. Review this screen carefully before tapping **Confirm**.
</Note>

<Steps>
  <Step title="Open the AI Updates tab">
    Launch the W-G-O NetNavi app and tap **AI Updates** in the bottom navigation bar.
  </Step>

  <Step title="Tap Import .wgo Package">
    Tap the **Import .wgo Package** button. The system file picker opens.
  </Step>

  <Step title="Select your file">
    Navigate to the location where you saved or received the `.wgo` file and tap it to select it.
  </Step>

  <Step title="Wait for validation">
    The app reads `manifest.json` and validates the schema. If validation fails — for example, because the `schema` field is incorrect or a declared file is missing — you will see an error message and the import will not proceed.
  </Step>

  <Step title="Review the diff preview">
    The app displays a summary of every change the package will apply. Check the XP before/after values for each character, the count of new history entries, any new or updated missions, and any rule or settings changes. If anything looks unexpected, tap **Cancel** and inspect your package files.
  </Step>

  <Step title="Confirm the import">
    Tap **Confirm** to apply the update. The app writes the changes to its local database and stores a backup of the previous state in case you need to roll back.
  </Step>
</Steps>

## Import JSON

Use this method when you have a standalone `data.json` file and do not need to include avatar models or images. It is the fastest path for a quick XP correction or rule update.

**Best for:** small adjustments, rule updates, or situations where you already imported avatars and only need to sync new data.

**Steps:**
1. In the **AI Updates** tab, tap **Import JSON**.
2. Select your `data.json` file from the file picker.
3. The app validates the JSON structure and displays the diff preview.
4. Review the changes and tap **Confirm** to apply.

Because there is no manifest file in this flow, the app skips manifest validation and goes straight to schema validation on the JSON content itself.

## Import GLB — Wallas or Melynna

Use these buttons when you want to replace a single character's 3D avatar model without touching any XP data. Each character has its own import button so you can update them independently.

**Best for:** swapping out a character model after a redesign, or fixing a corrupted avatar.

**Steps:**
1. In the **AI Updates** tab, tap **Import GLB — Wallas** or **Import GLB — Melynna** depending on which character you are updating.
2. Select the `.glb` file from the file picker.
3. The app displays a preview showing the model name and the list of animation clips it contains.
4. Confirm that the model and clip list look correct, then tap **Confirm** to replace the current avatar.

This import does **not** create a diff of XP data — the preview is limited to the 3D model metadata.

## Backup and Restore

Before every import of any kind, the app automatically saves a snapshot of the current app state as a local backup. You do not need to do anything to trigger this — it happens in the background as part of the import flow.

If an import produces unexpected results, you can roll back to the previous state:

1. Go to the **AI Updates** tab.
2. Tap **Restore Backup**.
3. Review the confirmation prompt, which shows the timestamp of the backup you are about to restore.
4. Tap **Confirm** to revert.

<Note>
  The app keeps only the **most recent backup**. Importing a second package overwrites the previous backup with a new snapshot taken just before that second import. If you need to undo multiple imports, restore the backup after each one before proceeding to the next import.
</Note>
